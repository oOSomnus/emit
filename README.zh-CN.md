# Emit

[English](README.md) | [简体中文](README.zh-CN.md)

本地运行的数字员工协作工作台：界面是 Slack 与邮箱的混合体，每个 agent 是一位有角色、技能、MCP 与工具权限的数字员工。

后端是一个 Node 进程，独占一个 SQLite 数据库与一个 [Pi Durable](https://earendil.com/posts/pi-durable/) harness。消息、邮件、工具调用、审批与运行记录都是持久化的 durable task 与 document：关掉浏览器任务继续跑；进程被强杀或断电后重启会恢复未完成的运行。

## 核心能力

- 每位员工有自己的模型与推理强度、技能绑定、MCP 绑定、允许的工具，以及被信任为只读的 MCP 工具列表。员工之间可以互相发消息、发邮件、交办任务，并由交办层数、唤醒次数与模型轮次预算阻止失控循环。
- 频道、私信与内部异步邮件。频道里只有在「指派员工」下拉框中显式指派才会唤醒员工；私信默认唤醒对应员工。交办工作的最终回答在「工作」页可见，也会回到发起会话。
- 会话拥有自己的工作目录：频道、私信与邮件线程各自保存服务器本地目录与默认执行目录，每轮工作都会保存目录快照。
- 邮件是持久且异步的：发信会先把正文、每位收件人的排队工作与派发任务落盘，之后才调用模型；关掉浏览器或进程被强杀都不会丢信。
- 自动风险审查：低、中风险自动批准，高风险进入人工队列，`deny`/`critical` 自动拒绝，未知风险或判断失败则阻止执行。
- 答案与完成状态在同一提交里写入；重启会恢复仍在运行的工作，并把无法恢复的工作标记为失败，被中断的工具只在声明可安全重放时才会重跑。

## 快速开始

需要 Node.js >= 22.19.0。

```bash
npm install
npm run dev          # 构建前端并启动后端（tsx watch）
```

打开 <http://127.0.0.1:8787> 完成首次设置：工作区名称（已有默认值）、你的名字、一个可用且推理强度受支持的默认对话模型，以及单独配置的审批判断模型（对话模型或 classifier）。审批判断不会暗中回退到员工模型。Provider 认证走各自的原生流程：API key、OAuth/订阅、云平台凭据，或进程环境中已有的凭据。

生产启动：

```bash
npm run build
npm start            # 需要已构建的 dist/web
```

默认数据目录是 `~/.emit`，同一时间只允许一个进程打开；保存的凭据不会回传给网页。[运行维护](docs/operations.zh-CN.md) 记录了数据文件、优先级与锁的行为。

## 安全边界

- 会话工作目录 **不是 OS 沙箱**。内置文件工具校验真实路径与符号链接，Shell 校验起始 cwd，但任意命令与 stdio/远程 MCP 仍以各自进程权限运行，目录列表不保证它们看不到其他路径。
- **自动风险审查不是沙箱**。它依据脱敏动作与有预算的上下文作判断，不能提供内核级只读保证，模型也可能误判。未知/失败会阻止执行，高风险需要人工，均不能替代进程隔离。
- 判断模型不是安全保证，也无法审计被预算省略的历史。
- 连接远程模型会把相应上下文发送给该 provider；只有连接本地模型时数据才不离开这台机器。
- Emit 默认监听回环地址（`127.0.0.1`），并且没有 SMTP 投递：外部邮件地址只是记录与显示。
