# 使用指南

[English](usage.md) | [简体中文](usage.zh-CN.md) · [项目主页](../README.zh-CN.md)

员工、协作、会话、邮件与界面的日常行为。审批规则见 [安全与审批](security.zh-CN.md)；CLI、数据文件与凭据见 [运行维护](operations.zh-CN.md)。

## 员工与协作

### 首次设置

- 工作区名称已预填默认值（`我的数字团队`），可以修改。
- 你的名字是必填项。
- 默认执行模型必须是目录中已配置的对话模型，且推理强度必须是该模型真正支持的等级；不满足时无法保存，界面会直接说明原因，而不是等到运行时才失败。
- 审批判断模型单独配置——可以是同一目录中的对话模型，也可以是 classifier。判断调用不提供工具，因此不要求一个「不支持工具」的模型，也绝不会暗中继承员工模型。「单独配置」并不意味着模型 ID 必须与员工不同。
- Provider 在首次设置向导或之后的「设置 → 模型 Provider」中配置，认证走各 provider 的原生流程（API Key、OAuth/订阅、云平台凭据）。未保存凭据的 provider 仍可使用进程环境变量作为等价来源。

### 员工配置

- 每位员工有执行模型与推理强度、技能绑定、MCP 绑定、允许调用的工具，以及被信任为只读的 MCP 工具列表。
- 模型必须是目录中存在、支持工具调用的对话模型，并且支持所选推理强度；否则保存会直接失败并说明原因。模型之后从凭据中被移除时，新工作会明确报错，不会静默换成别的模型。
- 工作目录不属于员工。修改员工配置会提升配置版本。
- 每位员工有一张生成的默认头像：由员工 id 稳定派生的圆角马赛克图案。改名不会改变图案，已删除员工的历史消息仍保留其图案，且不会请求任何网络资源；姓名与角色仍显示在图像旁边。

### 协作与交办

- 员工可以互相发消息、发邮件、交办任务。协作受交办层数、跨员工唤醒次数与模型轮次上限约束；把任务交办回自己的上级会被直接拒绝（会形成循环）。达到上限会停下来并说明原因，不会静默继续。
- 交办出去的工作，最终回答在「工作」页可见：打开「查看执行」可以看到真实步骤、工具调用、审批与最终回答。结果也会回到发起会话。

### 频道与私信

- 频道有明确的成员：创建时选择，之后可在「管理成员」中增删。员工也可以用 `invite_to_channel` 互相邀请；邀请立即生效，但不会启动被邀请的员工。所有成员都能读到频道的公开历史，包括自己加入之前的消息。
- 消息只唤醒被点名的员工。在输入框里输入 `@` 可以从本群 enabled 成员与 `@全体` 中选择，也可以使用成员 chip；输入框会实时预览谁会回复（`回复：A、B`）或提示「无人被点名」。`@全体` 启动当前全部 enabled 成员；disabled 成员会被跳过并说明。邮箱地址或代码里的 `@` 不会点名任何人。
- 未点名的消息同样会被记录——所有成员可见——但不会启动任何模型调用。之后加入的成员不会补发过去消息的唤醒，邀请本身也从不唤醒任何人。
- 重名必须用完整地址或 chip 消歧：有歧义的 `@名字` 会被直接拒绝，而不是猜测；点名非成员或 disabled 员工会在消息保存前被拒绝。
- 私信按工作隔离：同一员工在不同工作各有独立私信线程。员工之间的私信与用户私信并存；用户不能加入员工之间的线程，界面会把它显示为 `A ↔ B` 并禁用发送。
- 移除成员会停止该员工在这个频道里尚未完成的工作；其他成员的工作与已有消息不受影响。
- 只有用户真实发出的房间消息才构成人类授权；员工交办、工具结果与 synthetic user role 不会升级授权（见 [安全与审批](security.zh-CN.md)）。

## 工作、目录与共享笔记

- **工作**是一等对象——一个项目、一个 feature，或任意一件事。它拥有多个服务器本地目录加一个默认执行目录、目标、工作说明、file/url 资料与共享笔记。每个频道、私信与邮件线程都只属于一个工作；切换工作只影响接下来创建的东西，绝不会重新绑定已有会话。
- 在侧栏的「工作」页管理：名称、目标、工作说明、目录、file/url 资料与共享笔记。路径必须是绝对路径、必须存在且可访问；保存时会解析真实路径、去重并验证默认目录。url 资料只登记、不抓取；file 资料必须已存在于该工作的目录内。
- 目录不再属于会话。工作未配置目录时，本地 Shell 与普通文件访问不可用；已绑定到员工的技能目录仍可只读加载，远程 MCP 不依赖本地目录。
- 共享笔记是同一工作的会话之间唯一共享的记忆。员工只会在被要求时读取（`list_work_notes` / `read_work_note`）；目标、说明以及笔记与资料索引会进入提示词，其他会话的完整历史永远不会被自动加载。从私聊保存的笔记对同一工作的所有人可读——保存前界面会明确提示。一个工作的笔记对其他工作不可见，也只能在所属工作内读取。
- 每轮工作保存工作目录版本的快照。交办继承来源快照；新建私信或邮件线程只绑定工作，不复制快照。修改工作目录会立即作废**该工作所有房间**尚未执行的批准与等待审批的工作——旧工作后续调用必须停止并重新发送，已经开始执行的工具可以完成。修改目标、说明、资料或笔记不会使目录批准失效。

## 邮件

### 文件夹、搜索与阅读区

- 邮箱是 Gmail 的形状：左侧「收件箱 / 已发送 / 草稿 / 归档」，中间是紧凑的邮件行（未读加粗并带点），右侧是阅读区。窗口够宽时列表与阅读区并排；窗口变窄后阅读区替换列表并带返回按钮；窄屏下文件夹收进下拉选择器。
- 侧栏只有一个「邮箱」入口，显示未读总数。未读口径是：非用户发送、To/CC 含用户地址、非草稿、未归档、未读。收件箱、侧栏与实时的房间事件共用这一口径。
- 搜索按参与者、主题和正文匹配。「没有匹配的邮件」和「这个文件夹是空的」是两种不同的状态。

### 发送、收件人与回复

- 邮件自带收件人：To 里的每位员工各起一份异步工作；CC 只收到副本、不会启动任何工作；只发给用户自己的邮件也只是投递。
- 回复写给原发件人；回复自己已发送的邮件则写给原收件人。回复全部会带上原邮件的其他收件人，并排除自己与重复地址。
- 收件人可以从员工目录里选，也可以直接填地址。目录之外的地址按原样记录，但不会唤醒任何员工——只有员工会开始工作。

### 持久异步投递

- 发信就是排队：正文、每位收件人的排队工作与派发任务会在同一个提交里落盘，之后才调用模型。关掉浏览器、甚至进程被强杀，邮件不会丢；重启后收件人的工作继续。
- 邮件是异步的，不假装成聊天：阅读区不显示员工正在生成的字，而是给出这封邮件的工作状态——`排队中 / 进行中 / 等待审批 / 等待回信 / 已完成 / 失败 / 已停止`，以及「查看执行」弹层，里面是真实的输入、工具调用、工具结果与回答，可翻页看更早的步骤。等待中的工作可以在弹层里停止。
- 员工任务收到完整原邮件信封（发件人、To/CC、主题、父节点与正文）。员工的最终文本回答由系统自动投递为本邮件回复，所以普通回复无需调用 `send_mail`，也不需要工作目录。`send_mail` 用于主动另发邮件或创建协作分支。
- `send_mail` 带 `awaitReply: true` 时是一次真正的求助：发起方的工作停在「等待回信」，等待期间写出的答案会被扣住不投递；对方回信后，发起方带着回信原文继续，只投递一份最终答复。等待中的工作被停止时会一并清除等待关联；迟到的回信仍作为普通邮件送达，但不再被当成答案。
- 员工在邮件中调用 `send_mail` 默认延续当前 session，并以当前邮件为 `inReplyTo` 建立分支。显式 `newSession=true` 或非邮件来源会在同一工作内创建独立 session（仍使用该工作的目录，不复制目录快照）；跨 session 父节点会被拒绝。

### 草稿与写信

- 草稿保存在线程里，不投递也不唤醒任何人。草稿按条目单独列出：同一线程里的多份草稿各自可以继续编辑、发送或丢弃；保存编辑会退役旧版本，只留最新一版。
- 写信先选择工作；新线程固定属于它并使用该工作的目录，不复制当前阅读邮件的任何配置。草稿保留自己的线程与工作；回复留在被回复线程所属的工作里。
- 写信是右下角的固定弹层（窄屏全屏）。切换文件夹或翻看其他邮件不会丢掉没写完的内容；关闭时若还有未保存文本，会先问「保存草稿 / 丢弃 / 继续编辑」。手动保存草稿需要正文内容。
- 已读与归档是每封邮件自己的 flag：可以在列表行上直接标记。打开一个线程只会把你收到的未读邮件标为已读，而且每个线程每次会话只自动做一次；手动改回未读不会被立刻改回来。

### 地址与投递范围

- 地址形如 `名字@工作区.test`，只在本机使用，不会真的发出邮件。名字里的中文会保留在地址里；重名会加确定性后缀；用户的地址不会被员工占用。
- Emit 没有 SMTP 投递：外部地址只是记录与显示。

## 外观与导航

- 左栏包含工作区名称与工作选择器、频道与私信（各自独立滚动，并带「+」创建）、一个「邮箱」入口，以及底部固定的「审批 / 工作 / 执行记录 / 员工 / 设置」与外观、语言选择器。「工作」管理工作的目标、说明、目录、资料与笔记；「执行记录」是运行记录页。计数徽标只显示数量。
- 主题有浅色、深色、跟随系统三种。可以在侧栏底部、「设置 → 工作台」或首次设置里切换；选择存在浏览器本地，并在首帧之前应用，切换页面不会闪回旧配色。
- 界面支持英文与简体中文两种语言。语言选择器（侧栏底部、「设置 → 工作台」或首次设置）有三种状态：跟随浏览器、英语、简体中文。跟随浏览器时取浏览器首选语言（`zh*` → 简体中文，其余 → 英文）；选择保存在浏览器里，在首帧之前应用（包括 `<html lang>` 与文档标题），并在同源标签页之间同步。切换语言会就地在原处重绘界面与已在屏幕上的应用提示，不会刷新页面、重启进行中的工作或重新发送任何内容。只有界面文案与应用自身生成的消息会改变：用户内容、模型回答、第三方 provider 与 MCP 输出、执行记录原文都保持原样，早于翻译存在时保存的记录同样保留原文。
- 窄屏时左栏变成遮罩抽屉，由顶栏的菜单按钮打开。按 Escape 或点击遮罩会关闭并把焦点还给菜单按钮；选择导航项只关闭抽屉。表单与列表退成单列。
- 所有页面共用同一套间距、字号与语义颜色 token，定义在 `src/web/styles.css` 顶部的变量里；组件里不写死颜色。
